## 一、问题与修复对照

| # | 原问题 | 修复手段 |
| --- | --- | --- |
| 1 | 密码明文入库（`123456`），比对用 `equals` | 统一 BCrypt 加盐哈希：新增 `utils/PasswordUtils`，注册/新增/改密全部走 `encode()`，校验走 `matches()` |
| 2 | 登录响应回传整个用户对象（含 `password`） | `Account`/`User`/`Admin` 的 `password`、`newPassword` 字段加 `@JsonProperty(access = WRITE_ONLY)`：请求可写入、响应不返回 |
| 3 | 列表接口可拿到全站用户明文密码 | Mapper 的 `Base_Column_List` 去掉 `password` 列，列表/详情查询根本不查该字段（登录用的 `selectByUsername` 保留） |
| 4 | JWT 以用户密码为签名密钥 | 改用服务端独立密钥 `jwt.secret`（配置项）：改密不再导致他人 token 失效，也消除了弱密码被离线爆破的风险 |
| 5 | `/files/**` 整体排除在鉴权之外，上传/删除任何人可调 | 拦截器按请求方法区分：**GET 放行**（`<img src>` 无法携带 token，图片必须可显示），**上传 POST 与删除 DELETE 需登录态** |
| 6 | 上传不校验类型、沿用客户端原始文件名、可路径穿越 | 后缀白名单（png/jpg/jpeg/gif/webp/bmp）+ 服务端生成文件名（时间戳 + UUID）+ 路径参数校验，nginx 层同时拦截含 `..` 的 URI |
| 7 | 改密接口凭请求体中的 `username` 定位账号 | 非管理员强制使用当前登录用户的账号名，无法改他人密码 |

## 二、关键设计决策（面试可讲）

**1. 存量明文数据如何迁移？—— 登录时惰性升级（lazy upgrade）**
不做一次性批量刷库（需要停服、且容易漏），而是在登录校验时判断库中值是否为 BCrypt 格式（`$2a$/$2b$/$2y$`）：不是则按明文比对，比对通过后**立即加密回写**。老账号首次登录即完成迁移，用户无感。

**2. 为什么 `@JsonIgnore` 不行？**
`@JsonIgnore` 会同时禁用反序列化，导致登录、改密接口收不到请求体里的 `password` 字段，直接打死功能。必须用 `@JsonProperty(access = WRITE_ONLY)`——**只屏蔽响应，不屏蔽请求**。

**3. 为什么文件读取要放行？**
页面里的 `<img src="/files/xxx.png">` 由浏览器发起，无法附加自定义 token 请求头。若对 GET 也要求鉴权，全站图片立刻变裂图。因此按方法区分：读取开放、写入受限。真正的越权风险在上传与删除，已堵住。

**4. JWT 密钥为何要与密码解耦？**
改造前 `HMAC256(user.getPassword())` 有两个问题：用户改密会导致所有旧 token 失效（当前设计中可接受，但属耦合）；更严重的是密钥空间等于用户密码空间，弱密码可被离线爆破后伪造 token。改为服务端独立密钥后两个问题同时消失。

## 三、实测结果（10 组，全部符合预期）

| 组 | 验证项 | 结果 |
| --- | --- | --- |
| 1 | 存量明文密码登录 → 自动升级 | code 200；响应**无** `password` 字段；库中变为 `$2a$10$/CyTdKID...` |
| 2 | 升级后用密文比对再次登录 | code 200 |
| 3 | 错误密码 | code 5003 |
| 4 | 管理员登录 + 列表脱敏 | code 200、role `ADMIN`、响应无 `password`；`/user/selectPage`、`/admin/selectPage` 响应中 `"password"` 出现 **0 次** |
| 5 | 第三个账号登录（触发迁移） | code 200，库中同样变为 BCrypt 密文（3/3 账号完成迁移） |
| 6 | 改密码闭环（改走再改回） | 改密 200 → 新密码登录 200 → 旧密码登录 5003 → 改回 200 → 恢复登录 200 |
| 7 | 改密码归属校验 | 普通用户带他人 `username` 提交：请求 200，但**他人密码哈希未被改动**，且被强制改成了自己的密码 |
| 8 | 文件鉴权 | GET 图片无 token **200**（图片可显示）；POST 上传无 token **401**；`.txt` 上传 **400**（白名单）；`.png` 上传 200 且文件名为 `1790490472602-c8194662d8c941659e8152213d77d073.png`；DELETE 无 token **401**、带 token 200 |
| 9 | 路径穿越 | 经 Nginx **400**；直连后端 **400**（Tomcat 与业务层双重拦截） |
| 10 | RBAC 回归抽样 | 普通用户访问管理接口 403、业务接口 200、无 token 401（前一轮成果未被破坏） |

补充：前端 `PersonPage.vue`、`AdminPerson.vue` 的头像上传组件原本未携带 token（因旧配置免鉴权），已同步补上 `:headers="{ token: user.token }"`，并重新构建部署（产物 hash 更新至 `app.6b48df0b.js`）。

浏览器级验证：headless Chrome 渲染 `http://localhost/`，DOM 中出现「欢迎进入博客系统 / 请输入账号 / 请输入密码 / 还没有账号」，**未出现任何明文密码字样**，静态资源均从 80 端口加载。

## 四、使用与维护须知

- **数据库密码列现在是 BCrypt 密文**（形如 `$2a$10$...`）。今后若手工改库，密码必须写密文，或让用户走注册/改密接口。
- **JWT 密钥**位于 `application.yml` 的 `jwt.secret`，已生成随机值；**推送到公开仓库前务必改为环境变量注入**。
- 老 token 因密钥更换已全部失效，各账号重新登录一次即可（当前会话本就是新签发的）。
